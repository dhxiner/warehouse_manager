# Warehouse & Logistics API 

Асинхронный бэкенд-сервис (MVP) для управления складами и автоматизации логистических остатков, разработанный в рамках подготовки к лидерской программе ОЭЗ «Алабуга». 

Проект реализует полноценный CRUD-цикл с жестким контролем бизнес-логики физического мира (валидация вместимости складов перед добавлением или обновлением остатков товаров).

## Стек технологий
* **Python 3.10+** (асинхронная разработка)
* **FastAPI** (высокопроизводительный веб-фреймворк)
* **PostgreSQL** (реляционная СУБД для надежного хранения данных)
* **SQLAlchemy 2.0** (современная асинхронная ORM с использованием типов Mapped)
* **Alembic** (асинхронная система миграций базы данных)
* **Pydantic v2** (строгая валидация входящих и исходящих данных на основе типов)

## Архитектура и связи данных
Реализована реляционная связь **«Один ко многим» (One-to-Many)** между таблицами Складов (`warehouses`) и Товаров (`items`):
* Каждый товар жестко привязан к конкретному складу через `ForeignKey`.
* Настроено **каскадное удаление** (`cascade="all, delete-orphan"`): при удалении склада автоматически очищаются все связанные с ним товары.

## Ключевая бизнес-логика
В проекте реализован сложный механизм защиты от переполнения складов (`PATCH /items/{item_id}/quantity`):
1. На основе агрегатной функции `func.sum` бэкенд асинхронно рассчитывает суммарную загруженность конкретного склада.
2. При попытке обновить остатки товара система вычисляет будущую загрузку по формуле: `Все_товары - Старый_объем + Новый_объем`.
3. Если лимит склада (`capacity`) превышен, транзакция отменяется, а клиенту возвращается ошибка `400 Bad Request`.

## Как запустить проект локально

1. **Клонировать репозиторий:**
   ```bash
   git clone https://https://github.com/dhxiner/warehouse_manager
   ```

2. **Создать и активировать виртуальное окружение:**
   ```bash
   python -m venv venv
   # Для Windows:
   venv\Scripts\activate
   # Для Mac/Linux:
   source venv/bin/activate
   ```

3. **Установить зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Настроить окружение:**
   Создайте файл `.env` в корне проекта и укажите строку подключения к вашей PostgreSQL:
   ```env
   DATABASE_URL=postgresql+asyncpg://postgres:ваш_пароль@localhost:5432/имя_базы
   ```

5. **Применить миграции базы данных:**
   ```bash
   alembic upgrade head
   ```

6. **Запустить сервер:**
   ```bash
   uvicorn main:app --reload
   ```

После запуска интерактивная документация API доступна по адресу: `http://127.0.0.1:8000/docs`
