# Warehouse & Logistics Managment System 

Высокопроизводительный асинхронный бэкенд-сервис (Production-Ready API) для комплексного управления складами, автоматизации логистических остатков и ролевого контроля доступа.

Сервис реализует полноценный CRUD-цикл, защищён сквозной системой авторизации (JWT + Bcrypt), содержит модуль сквозного логирования операций (Audit Trail) и автоматическую генерацию бизнес-отчётов в формате Excel.

## Стек технологий и инструменты
* **Язык разработки:** Python 3.10+ (Асинхронный стек)
* **Веб-фреймворк:** FastAPI (Uvicorn, StreamingResponse)
* **СУБД и ORM:** PostgreSQL + SQLAlchemy 2.0 (Асинграммный драйвер `asyncpg`, типы `Mapped`, агрегатные функции `func.sum`)
* **Миграции БД:** Alembic (Полностью асинхронный шаблон `env.py`)
* **Безопасность:** PyJWT (JSON Web Tokens), Passlib с алгоритмом Bcrypt (Хеширование паролей)
* **Валидация данных:** Pydantic v2 (Использование `PositiveInt`, `Literal` ограничений)
* **Аналитика:** OpenPyXL (Формирование динамических бинарных потоков `.xlsx`)

## Архитектура базы данных и сущности
Спроектирована отказоустойчивая реляционная структура данных:
1. **`Warehouse` (Склады):** Хранит лимиты вместимости (`capacity`). Имеет связь «Один ко многим» со связанными товарами с настроенным каскадным удалением (`cascade="all, delete-orphan"`).
2. **`Item` (Товары):** Жестко привязан к складу через `ForeignKey`.
3. **`User` (Пользователи):** Поддерживает ролевую модель (RBAC) со строгим уникальным логином (`unique=True`).
4. **`StockLog` (Журнал аудита):** Независимая историческая таблица для фиксации логов (Audit Trail). Специально спроектирована без внешних ключей, чтобы сохранять историю операций даже после физического удаления складов или товаров. Включает автотаймстампы (`server_default=func.now()`).

## Реализованная продвинутая бизнес-логика

### 1. Ролевой доступ (RBAC) и Криптография
* Пароли пользователей никогда не хранятся в открытом виде — при регистрации они необратимо хешируются алгоритмом **Bcrypt** (длина слепка — до 100 символов).
* Сессии пользователей управляются временными токенами **JWT (Bearer)** со сроком жизни 30 минут. Секретные ключи подписи (`SECRET_KEY`) изолированы в файле `.env`.
* Создана кастомная инфраструктура проверки прав `RoleChecker` на базе зависимостей FastAPI. Доступ разграничен между тремя ролями:
  * `admin` — Полный доступ к управлению складами, товарами и изменению ролей сотрудников.
  * `manager` — Разрешено добавление товаров и изменение остатков. Блокирован доступ к удалению складов.
  * `viewer` — Доступ в режиме «Только чтение» (`GET` запросы). Любые деструктивные действия вызывают ошибку `403 Forbidden`.

### 2. Защита от переполнения складов
В эндпоинте изменения остатков (`PATCH /items/{id}/quantity`) реализован строгий контроль: система асинхронно рассчитывает будущую загрузку склада по формуле: `Все_товары_склада - Старый_объем_товара + Новый_объем`. Превышение лимита атомарно откатывает транзакцию и возвращает ошибку `400 Bad Request`.

### 3. Enterprise-пагинация и Поиск
Эндпоинты чтения защищены от перегрузки оперативной памяти (Out of Memory):
* Реализован постраничный вывод на базе связанных методов `.limit(limit).offset(offset)`.
* Интегрирован гибкий регистронезависимый поиск по подстроке названия товара через оператор `.ilike(f"%{search}%")`.

### 4. Автоматическая бизнес-отчётность (Excel Export)
Защищённый эндпоинт `GET /warehouses/{id}/export` на лету собирает срез остатков склада, вычисляет финансовые показатели, упаковывает данные в бинарный поток `io.BytesIO()` и без создания временных файлов на диске отправляет руководителю скачиваемый файл `.xlsx` через `StreamingResponse`.

## Порядок локального запуска

1. **Клонировать репозиторий:**
   ```bash
   git clone https://https://github.com/dhxiner/warehouse_manager
   ```

2. **Развернуть виртуальное окружение и установить зависимости:**
   ```bash
   python -m venv venv
   # Активация для Windows:
   venv\Scripts\activate
   
   pip install -r requirements.txt
   ```

3. **Настроить переменные окружения:**
   Создайте файл `.env` в корневой директории:
   ```env
   DATABASE_URL=postgresql+asyncpg://postgres:ваш_пароль@localhost:5432/warehouse_db
   SECRET_KEY=your_generated_random_64_character_hex_string
   (либо использовать пример ключа: SECRET_KEY=9a8b7c6d5e4f3210987654321fedcba09876543210fedcba9876543210abcdef)
   ALGORITHM=HS256
   ```

4. **Применить асинхронные миграции к PostgreSQL:**
   ```bash
   alembic upgrade head
   ```

5. **Запустить сервер приложений:**
   ```bash
   uvicorn main:app --reload
   ```

*Интерактивная документация API, включая ролевую авторизацию по кнопке Authorize, доступна по адресу:*`http://127.0.0.1:8000/docs`
